# Frontend 담당자 시작 가이드

> 작성: 2026-09-29 · Backend & Cloud
> Backend를 내 PC에서 띄우고 API를 테스트하는 방법입니다.

---

## 1. 준비물

- **Docker Desktop** (필수)
- Git
- Python은 필요 없습니다

Backend 담당에게 받을 것:

- `DATABASE_URL` (Azure 공유 DB 접속 주소)
- 접속 IP 등록 (집에서 작업하면 https://api.ipify.org 결과를 전달)

---

## 2. Backend 띄우기

### 2-1. 가장 간단한 방법 (AI 없이, 화면 개발용)

AI는 가짜 결과를 돌려주지만 API 흐름은 똑같습니다. **화면 개발에는 이걸로 충분합니다.**

```bash
git clone https://github.com/seominji58/drawtale-backend.git
cd drawtale-backend
git checkout dev

cp .env.example .env
# .env 파일을 열어 DATABASE_URL을 전달받은 주소로 바꿉니다

docker compose --profile app up -d --build
```

- 첫 실행은 5~10분 걸립니다
- 완료: http://127.0.0.1:8000/docs 접속
- 로그: `docker compose logs -f backend`
- 종료: `docker compose --profile app down`

### 2-2. 실제 애니메이션까지 보려면

AI 서버도 함께 띄웁니다. **첫 빌드가 30~60분 걸립니다.**

```bash
# 1) AI 서버 (다른 폴더에서)
git clone https://github.com/seominji58/drawtale-ai.git
cd drawtale-ai
git checkout dev
docker compose up -d

# torchserve가 healthy가 될 때까지 기다립니다 (1~2분)
docker compose ps

# 2) Backend의 .env에서 아래 한 줄을 바꾸고 다시 띄웁니다
#    AI_USE_MOCK=false
cd ../drawtale-backend
docker compose --profile app up -d
```

## 3. API 테스트

**http://127.0.0.1:8000/docs** 에서 바로 해볼 수 있습니다.

### 3-1. 그림 업로드

`POST /api/v1/characters` → Try it out → 그림 선택 → Execute

```json
{
  "character_id": "68510684-...",
  "job_id": "b2f38c23-...",
  "status": "pending"
}
```

### 3-2. 진행 상태 확인 (polling)

`GET /api/v1/jobs/{job_id}` 를 **1~2초 간격으로** 호출합니다.

- `status`가 `succeeded` 또는 `failed`가 되면 멈춥니다
- 분석은 2~3초 걸립니다

### 3-3. 관절 조회

`GET /api/v1/characters/{character_id}`

- `joints`: 현재 관절 15개 (사용자가 수정했으면 수정값)
- `analysis.joints`: AI 원본 관절 (변하지 않음)
- `image_url`: 원본 그림
- 좌표는 **원본 이미지 픽셀 기준**입니다. 화면 크기에 맞춰 변환해서 그리세요

### 3-4. 관절 수정

`PATCH /api/v1/characters/{character_id}/joints`

**15개 전부** 보내야 합니다. 움직이지 않은 관절도 포함합니다.

### 3-5. 이야기 + 애니메이션 생성

`POST /api/v1/stories`

```json
{
  "character_id": "68510684-...",
  "place": "학교",
  "problem": "친구와 다퉜어요",
  "action": "먼저 사과해요",
  "result": "다시 사이좋게 놀아요"
}
```

- `job_id`로 상태를 확인합니다
- **실제 AI 사용 시 30~40초 걸립니다.** 대기 화면이 필요합니다
- 완료되면 `GET /api/v1/stories/{story_id}`의 `animation_url`에 MP4 주소가 들어옵니다

---

## 4. 전체 화면 흐름

```text
1. 그림 업로드
     ↓ 2~3초 (로딩 표시)
2. 관절 15개를 그림 위에 표시
     ↓ (필요하면 수정)
3. 장소 → 문제 → 행동 → 결과 선택
     ↓ 30~40초 (대기 화면 필요)
4. 이야기 텍스트 + 애니메이션 MP4 재생
```

## 5. 자주 겪는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| DB 연결 실패 | 현재 IP가 방화벽에 없음 | https://api.ipify.org 결과를 Backend 담당에게 전달 |
| CORS 오류 | Frontend 개발 포트가 등록 안 됨 | 쓰는 포트를 Backend 담당에게 알려주세요 |
| `animation_url`이 `null` | 아직 만드는 중 | `status`가 `succeeded`가 될 때까지 기다립니다 |
| 이야기 생성 시 타임아웃 | `AI_TIMEOUT_SECONDS`가 짧음 | `.env`에서 `300`으로 설정 |
| 그림 분석 실패 | 사람 형태 인식 안 됨 | `error.code`가 `NO_CHARACTER_DETECTED`. 다른 그림으로 시도 |

## 6. 알아두면 좋은 것

### 관절 15개 이름

```
hip, torso, neck,
right_shoulder, right_elbow, right_hand,
left_shoulder, left_elbow, left_hand,
right_hip, right_knee, right_foot,
left_hip, left_knee, left_foot
```

`right`/`left`는 **그림 속 캐릭터 기준**입니다. 캐릭터의 오른손은 화면에서 왼쪽에 보입니다.

### 에러 응답 형식

```json
{
  "error": {
    "code": "NO_CHARACTER_DETECTED",
    "message": "그림에서 사람 모양 캐릭터를 찾지 못했어요.",
    "detail": null
  }
}
```

`message`는 **사용자에게 그대로 보여줘도 되는 한국어 문장**입니다.

### 현재 미구현

- 음성(TTS): `audio_url`이 항상 `null`
- 이야기 텍스트: 아직 템플릿 문장 (OpenAI 연동 예정)

### 관절 정확도

AI 모델이 사람 사진으로 학습되어, 4등신 캐릭터 그림에서는 관절이 안쪽으로 몰리는
경향이 있습니다. 애니메이션에서 팔다리가 다소 휘어 보일 수 있습니다.

## 7. 함께 정할 것

- **이야기 4단계 선택지 형식**: 지금은 자유 문자열(50자)입니다. 정해진 선택지 목록을
  서버가 내려줄지 정해야 합니다
- **polling 간격**: 1~2초를 제안합니다
- **Frontend 개발 포트**: CORS 등록이 필요합니다
